## Область применения

- Формы редактирования.
- Сведения из профиля пользователя.
- Настройки, к которым нужен доступ с текущей страницы.

## Анатомия

В свойство `header` можно передать [`ModalPageHeader`](/components/modal-page-header). Остальные части окна создаёт библиотека.

- `ModalOutlet` размещает окно поверх страницы с помощью контейнера с фиксированным позиционированием.
- `ModalOverlay` создаёт интерактивную подложку.
- `ModalPageInternal` управляет поведением окна.
- `ModalPageContent` оборачивает содержимое `children` в [`CustomScrollView`](/components/custom-scroll-view).

## Поведение

Свойство `open` открывает и закрывает окно. По умолчанию оно закрыто. При `open={false}` компонент размонтируется. Чтобы сохранить его в DOM, передайте `keepMounted`.

Компонент анимирует окно и подложку. Он вызывает `onOpen` в начале открытия, `onOpened` после открытия и `onClosed` после закрытия. Когда пользователь пытается закрыть окно, компонент вызывает `onClose` и передаёт причину. Чтобы закрыть окно, установите `open={false}`.

В обоих режимах открытое окно удерживает фокус внутри себя при навигации с помощью `Tab` и `Shift` + `Tab`.

> Когда открываете модальное окно поверх другого, задайте нижнему окну `disableFocusTrap`, чтобы верхнее могло удерживать фокус.

### Настольный режим

В настольном режиме `ModalPage` выглядит как диалоговое окно. Свойство `size` ограничивает его максимальную ширину.

Настольный режим включается при ширине от 768 пикселей, если у устройства есть указатель или высота области просмотра достигает `ViewHeight.MEDIUM`. На платформе `vkcom` настольный режим включён всегда.

По умолчанию `onClose` получает один из следующих аргументов.

- `click-close-button` при нажатии на кнопку закрытия.
- `click-overlay` при нажатии на подложку `ModalOverlay`.
- `escape-key` при нажатии `Esc`.

### Мобильный режим

В мобильном режиме `ModalPage` выдвигается снизу как панель (bottom sheet).

> Если в [`ConfigProvider`](/components/config-provider) передать `hasCustomPanelHeaderAfter`, над панелью появится отступ высотой с [`PanelHeader`](/components/panel-header). Отступ защищает кнопку закрытия от перекрытия плавающим элементом, например панелью управления WebView.

По умолчанию `onClose` получает один из следующих аргументов.

- `click-overlay` при нажатии на подложку `ModalOverlay`.
- `escape-key` при нажатии `Esc`.
- `swipe-down` при смахивании или перетаскивании панели вниз по правилам ниже.

#### Взаимодействие через тач или указатель мыши

> `<ConfigProvider platform="vkcom" />`
>
> Платформа `vkcom` включает настольный режим. Высота окна зависит от содержимого, а перетаскивание отключено.

Свойство `settlingHeight` задаёт начальную высоту панели в процентах от высоты экрана. Допустимые значения — от `25` до `100`. По умолчанию используется `50`.

- При `settlingHeight <= 90` пользователь может раскрыть панель до полной высоты экрана и свернуть её до начальной высоты.
- При `settlingHeight > 90` панель всегда открывается на полную высоту экрана.

Чтобы высота панели зависела от содержимого, используйте `dynamicContentHeight` вместо `settlingHeight`.

При перетаскивании панели вниз подложка `ModalOverlay` становится прозрачнее. При заданном `settlingHeight` прозрачность рассчитывается относительно начальной высоты панели.

Компонент вызывает `onClose('swipe-down')` в трёх случаях.

- Высота панели достигла нуля во время перетаскивания.
- Пользователь отпустил панель ниже половины начальной высоты при `settlingHeight` или ниже половины высоты содержимого при `dynamicContentHeight`. Например, при `settlingHeight={50}` панель закроется при высоте меньше 25% высоты экрана.
- Пользователь резко смахнул панель вниз. При `settlingHeight` это срабатывает только с начальной высоты панели.

Перетаскивание блокируется, пока пользователь взаимодействует:

- с содержимым `ModalPageContent`, если `disableContentPanningGesture={false}` и `scrollTop !== 0`;
- с горизонтальной прокруткой, текстовым полем или выделенным текстом;
- с элементом, который вызывает `event.stopPropagation()` в `onTouchStart` или `onMouseDown`;
- с элементом с атрибутом `data-vkui-block-sheet-behavior`. Этот атрибут используется, в частности, при `disableContentPanningGesture={true}`.

## Хук `useModalManager`

Чтобы управлять модальными окнами, воспользуйтесь хуком [`useModalManager`](/components/use-modal-manager).

## Доступность (a11y)

У `ModalPage` с ролью `dialog` должно быть доступное имя. Скринридер объявляет его при открытии окна.

Имя можно задать через `title`, `aria-label` или `aria-labelledby`. Если вложить [`ModalPageHeader`](/components/modal-page-header), он свяжет свой заголовок с окном через `aria-labelledby`.

## FAQ

### Как поменять максимальную ширину контента?

Используйте параметр `size`.

### Как задать фиксированную высоту контента?

Передайте высоту числом в пикселях (`height={300}`) или строкой с процентами (`height={'80%'}`).

> В мобильной версии на высоту по умолчанию также влияет значение `settlingHeight`. Чтобы отключить его влияние, достаточно задать
> `settlingHeight={100}`.

### Как правильно применять параметр `autoFocus`?

В React `autoFocus` может прервать CSS-анимацию открытия. Чтобы сфокусировать поле после анимации, вызовите `focus()` в обработчике `onOpened`.

{/* @example-description: Ручной фокус в поле ввода `ModalPage` после завершения анимации открытия. */}
<Playground>

```jsx
const [open, setOpen] = React.useState(false);

const inputRef = React.useRef(null);

const handleOpen = React.useCallback(() => {
  if (inputRef.current) {
    inputRef.current.focus();
  }
}, []);

return (
  <>
    <Button onClick={() => setOpen(true)}>Открыть</Button>
    <ModalPage
      id="modal-with-auto-focus"
      open={open}
      onOpened={handleOpen}
      onClose={() => setOpen(false)}
    >
      <Box padding="system">
        <Input getRootRef={inputRef} />
      </Box>
    </ModalPage>
  </>
);
```
