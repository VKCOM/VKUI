# Документация на сайте VKUI

## Выбери версию

1. Проверь `package.json` приложения, файл блокировки зависимостей и, если пакет установлен, его `@vkontakte/vkui/package.json`. Если в `package.json` указан диапазон версий, используй точную версию из файла блокировки или установленного пакета. В монорепозитории VKUI смотри `packages/vkui/package.json` и локальный исходный код.
2. Если пользователь явно указал другую целевую версию, используй её. Не обновляй зависимость только ради совпадения с примером.
3. Возьми за основу адрес `https://vkui.io/{version}/` и подставь точную версию. Если версию определить не удалось, используй документацию без версии и сообщи об этом допущении.
4. Если у выбранной версии нет опубликованной документации, используй её установленные декларации TypeScript и локальный исходный код. Не подменяй её более новой мажорной версией без согласования. Если в рабочей копии есть изменения, которые ещё не выпущены, сверяйся с рабочей копией в первую очередь.

## Найди компоненты и проверь их API

Ищи страницы компонентов и хуков в `llms.txt` выбранной версии. В ссылках из индекса заменяй `https:/vkui.io/` в начале адреса на `https://vkui.io/`. Если индекс недоступен или ссылка не открывается, найди страницу через навигацию по документации той же версии. Из имён с аббревиатурами и имён вложенных компонентов не всегда можно вывести адрес простым преобразованием в kebab-case. Выбирай компоненты по их назначению и примерам в документации.

Прочитай страницу компонента или хука до изменения кода. Чтобы получить документацию API и примеры в текстовом виде, отправь заголовок `Accept: text/markdown` в запросе к `vkui.io`. Для проекта с версией 8.3.0 подойдёт такая команда.

```sh
curl -fsSL -H 'Accept: text/markdown' 'https://vkui.io/8.3.0/components/button/'
```

Если инструмент не позволяет задать заголовок или сервер возвращает HTML, поищи ссылку на `.mdx` на странице или в индексе выбранной версии. Если ссылки нет или `.mdx` недоступен, прочитай HTML-страницу той же версии. Так же открывай руководства из таблицы ниже.

Запрашивай только страницы, которые нужны для задачи. Если в документации не хватает сведений о типах, в том числе сложных или унаследованных, проверь установленные декларации TypeScript или локальный исходный код. По ошибке HTTP нельзя судить, существует ли компонент или проп.

## Настрой и собери интерфейс

Открывай нужные руководства по указанным путям относительно базового адреса документации.

| Задача                               | Руководство               |
| ------------------------------------ | ------------------------- |
| Зависимости, импорт CSS и провайдеры | `overview/install/`       |
| Базовая компоновка                   | `overview/usage/`         |
| Адаптивность и плотность интерфейса  | `overview/adaptivity/`    |
| Настройка тем                        | `overview/themes/`        |
| Дизайн-токены                        | `overview/design-tokens/` |
| Серверный рендеринг                  | `overview/ssr/`           |
| Навигация                            | `overview/navigation/`    |

По другим темам ищи ссылки в индексе выбранной версии. Если используешь документацию без версии, открывай `https://vkui.io/llms.txt`.

Сохраняй иерархию провайдеров приложения, точку подключения стилей, маршрутизацию и принятый способ настройки темы. Для нового приложения подключай обязательные провайдеры и CSS по руководству по установке для выбранной версии. В существующем интерфейсе на VKUI отдавай предпочтение задокументированным компонентам и токенам. Проверяй поведение интерфейса на нужных платформах и при разных параметрах адаптивности, даже если пример работает на компьютере.

Проверь сигнатуры колбэков, управляемое состояние, рефы и элемент, которому передаются пропы. При работе с `slotProps` проверь точное имя слота и объедини новые и существующие пропы слота, чтобы сохранить обработчики и рефы. При адаптации примеров сохрани доступные имена элементов, клавиатурное управление и управление фокусом.

## Проверь изменения

Запусти нужные проверки типов и существующие тесты. Проверь затронутые сценарии взаимодействия и вёрстку. Укажи целевую версию VKUI и открытые вопросы по API.
